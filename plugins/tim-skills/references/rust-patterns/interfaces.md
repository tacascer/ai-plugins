# Traits and public interfaces

**Fit.** Use for reusable APIs, dispatch choices, and compatibility reviews. Keep a concrete function or enum when the implementation set is small and known. Introduce traits for a real substitution boundary, not merely to make every collaborator mockable.

**Dispatch.** Generics and argument-position `impl Trait` let callers select a concrete implementation and support static dispatch. They can increase generated code and compile work; measure before extracting a non-generic inner implementation. `&dyn Trait` supports runtime heterogeneity without inherently requiring a heap allocation; `Box<dyn Trait>` adds ownership and allocation. Return-position `impl Trait` hides a concrete implementation chosen by the function; it is not arbitrary runtime type erasure. Choose associated types when the implementation determines a related type, and trait parameters when multiple relationships are intentional.

**Compatibility.** Check dyn compatibility (historically object safety) before promising trait objects. Generic methods and certain uses of `Self` can prevent dispatch; `where Self: Sized` can exclude a helper from trait-object use. Inspect today's rules for async methods and opaque returns instead of transferring the early edition's limitations wholesale. [Trait rules](https://doc.rust-lang.org/reference/items/traits.html).

Trace downstream implementations before adding blanket impls or tightening bounds. The number of impl generic parameters need not equal the number of trait arguments. Orphan legality and overlapping implementations are separate checks; foreign trait implementations can involve a local trait argument, so “Self must always be local” is insufficient. [Coherence](https://doc.rust-lang.org/reference/items/implementations.html#trait-implementation-coherence). New required methods, lost auto traits, and loss of dyn compatibility can break users even when function names are unchanged. A sealed trait intentionally restricts implementers; it is not a universal default. [Compatibility](https://doc.rust-lang.org/cargo/reference/semver.html).

**Ergonomics.** Use `AsRef` for inexpensive views and `Borrow` only when its equality, ordering, and hashing equivalence contract holds. `Deref::deref` takes `&self`, not ownership of `self`; account for the distinct `DerefMut` and `AsRef` receiver/conversion roles too. `Deref` exposes implicit coercions and inner methods: use it deliberately for pointer-like behavior, not inheritance or bypassing a validated wrapper. Prefer explicit accessors when the wrapper has a different contract. `Cow` is useful when results can sometimes borrow and sometimes allocate. `String::from_utf8_lossy` borrows its input; invalid UTF-8 produces an owned repaired result, not ownership transfer of the input. [String API](https://doc.rust-lang.org/std/string/struct.String.html#method.from_utf8_lossy).

**State and cleanup.** Use typestate when compile-time transitions simplify a meaningful protocol; prefer an enum and checked transition for runtime-dependent state. Document panic, error, and safety contracts. Provide an explicit fallible or async finish/close operation when callers must observe cleanup failure; `Drop` cannot return that result or await completion.

**Verification.** Compile representative downstream callers, trait implementations, and trait-object use. Include a no-change case: a concrete borrowed API with no substitution requirement needs no new generic abstraction.

**Reusable ecosystem patterns.** Index handles can replace self-references when a collection owns the data; define invalidation on removal, reordering, and slot reuse, using generations if stale handles must be detected. Extension traits add methods to foreign types without changing their base trait. Keep crate preludes small and review method ambiguity introduced by glob imports. These are choices with contracts, not obligatory abstractions.
