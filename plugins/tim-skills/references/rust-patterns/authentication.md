# Credentials and sessions

**Problem and fit.** Password and session handling crosses a security boundary. Use a maintained, established password-hashing and session integration appropriate to the existing stack; do not implement a password hash or token generator from scratch. Treat session IDs, bearer tokens, and password material as credentials, including in `Debug`, spans, metrics, and error context. This reference guides architecture; it does not certify an implementation. [Current OWASP guidance](sources.md#current-primary-sources-and-bounded-alternatives).

**Shape and trade-offs.** Use an adaptive password hash with a unique salt and parameters selected against current guidance and measured resource cost. Verification is deliberately expensive: on an async service, put synchronous verification behind a bounded blocking boundary or suitable existing adapter, and limit concurrent work. Moving it off executor workers alone does not bound CPU or memory use; started Tokio blocking tasks normally continue after cancellation. Preserve safe failure responses and avoid revealing whether an account exists through unnecessary detail. [OWASP password source](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html); [Tokio source](sources.md#current-primary-sources-and-bounded-alternatives).

**Browser sessions.** Use HTTPS and deliberate `Secure`, `HttpOnly`, and `SameSite` cookie attributes suited to the application's navigation and CSRF model. Keep session identifiers out of URLs and logs; establish rotation, expiry, invalidation, and storage behavior with the chosen session library. `SameSite` is defense in depth, not a complete CSRF design. Check framework and library versions before suggesting a method or default. [OWASP session source](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html).

**Review questions.** Which library owns hashing and sessions? What executes synchronously on runtime workers? Is concurrent verification bounded? Are sensitive arguments captured automatically? Are cookie attributes and session lifecycle explicit?
