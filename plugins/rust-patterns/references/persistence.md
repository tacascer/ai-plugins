# Persistence decisions

**Problem and fit.** Choose a query interface that fits the team's query forms, schema workflow, build tool, and pinned versions; retain a working adapter for a small feature when it meets the requirement. No query library makes an incompatible runtime schema safe by itself. [Source synthesis](sources.md#current-primary-sources-and-bounded-alternatives).

**Options.** SQLx's literal `query!` checks SQL against a build-time database or prepared offline metadata; dynamic SQL does not take that macro's inspection path. Diesel's schema-backed DSL gives typed, composable queries and compile-time mapping checks. Hand-written analytical SQL may favor the former, while composable filters may favor the latter; check versions, MSRV, backend support, async adapter, feature flags, and build integration. A private fork with unavailable docs calls for pattern-level advice and explicit API uncertainty, never invented methods. [SQLx and Diesel sources](sources.md#current-primary-sources-and-bounded-alternatives).

**Pool and transaction shape.** Construct a pool at service scope, pass it through existing state, and bound acquisition and query time as the contract needs. When two owned database writes must appear together, begin one transaction, execute both against that transaction, and commit only after both succeed. Check failure injection between writes. A request, two `execute(pool)` calls, or an external HTTP call is not automatically one transaction. SQLx documents rollback on drop for an uncommitted transaction; verify the pinned adapter's semantics. Local rollback cannot undo arbitrary remote effects. [SQLx transaction source](sources.md#current-primary-sources-and-bounded-alternatives).

**Migration compatibility.** If old and new service versions overlap, add a compatible column or path, backfill, switch reads/writes, verify both versions during overlap, then remove the old field after old readers are gone. Dropping a column still read by an older version breaks it. Ask: which versions coexist, where is each write committed, what happens on second-write failure, and which checks depend on build-time schema metadata? [Book principle](sources.md#verified-book-principles).
