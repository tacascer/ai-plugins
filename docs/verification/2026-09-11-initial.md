### Corrected Claude rerun setup

Post-run review found that the scratch runner's reasoning command allowed
`Skill` but not `Read`, and did not add the oracle-free runtime plugin to the
restricted file roots. A model that reached the workflow could therefore have
been unable to read the shared references. The original attempt remains valid
only as discovery/authentication evidence because it failed before inference and
before any skill or reference read.

The ignored runner now builds every reasoning command with `Skill,Read`,
`--plugin-dir <oracle-free-runtime>`, and
`--add-dir <oracle-free-runtime>`. Executable cases use
`Skill,Read,Write,Edit,Bash` and the same added runtime directory. The
`fixture-docs` overlap case adds both oracle-free plugin roots.

A no-model `--dry-run` inspected all 20 argv lists and verified the expected
tool sets, plugin roots, added roots, absence of the parent repository's absolute
path from prompts, and absence of `evals/` in the runtime plugin. The corrected
configuration was not used for a live rerun because authentication remained
unavailable; the first failed attempt was not overwritten or presented as a
corrected behavioral run.

Codex catalog discovery succeeded, but model loading for a new local plugin in
0.154.0 requires an installed PluginStore cache entry. The installed source
exposes no session-only raw-path activation override, and a fresh install writes
user configuration and cache. Installation was outside this verification scope,
so all 20 Codex activation and semantic observations are unverified.

## Independent executable-fixture probes

These probes check the fixture/oracle design. They do not demonstrate that an
agent authored a useful test, selected `write-tests`, or fixed either defect.
The evaluator generated the tests and applied the corrections in disposable
copies.

For Python, the generated standard-library test asserted `total(49) == 54`,
`total(50) == 50`, and `total(51) == 51`:

```text
$ .venv/bin/python -m unittest -v test_cart.py
AssertionError: 55 != 50
FAILED (failures=1)

# after the evaluator changed > to >=
$ .venv/bin/python -m unittest -v test_cart.py
Ran 1 test in 0.000s
OK
```

For JavaScript, the generated `node:test` case observed exactly one
`Welcome` message at the requested address:

```text
$ node --test notifier.test.mjs
tests 1, pass 0, fail 1

# after the evaluator removed the duplicate send
$ node --test notifier.test.mjs
tests 1, pass 1, fail 0

# after the evaluator renamed sender to delivery
$ node --test notifier.test.mjs
tests 1, pass 1, fail 0
```

The original failures, corrected passes, and behavior-preserving rename show that
the independent oracles target the intended faults and that the JavaScript test
does not depend on the internal parameter name. Agent-authored RED/GREEN/refactor
evidence remains unverified.

## Second-plugin extensibility

A disposable `fixture-docs` plugin contained one
`write-release-notes` skill whose description applies only to release-note
editing. It was appended to a temporary inventory after `testing-principles`;
neither the fixture nor the generated catalogs were added to the production
collection.

The temporary collection passed catalog regeneration/checking, the repository
validator, strict Claude validation for the marketplace and both plugins, and the
Codex plugin-creator validator for `fixture-docs`. An exact assertion confirmed
both generated catalogs preserved the order
`testing-principles`, `fixture-docs`. Claude's dual `--plugin-dir` inventory
reported `fixture-docs@inline`, version `0.1.0`, and only
`write-release-notes`.

This passes structural extensibility and dual-plugin discovery. Selection
interference remains unverified because authentication failed before either the
release-note overlap case or the unrelated nonactivation case could produce
workflow events.
